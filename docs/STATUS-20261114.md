## Result modal defect

The reported narrow strip was reproducible from the extension's close behavior: JavaScript set `hidden` on the result, but `.result { display: flex }` overrode the browser's default `[hidden]` rule. The closed result stayed inside the 38 px floating control and wrapped every word into a thin column. `chrome-extension/src/modal.css` now gives `hidden` precedence and explicitly hides result content while the control is collapsed. The built extension is **1.3.36**. No classifier, source, or media decision rule changed for this fix.

The current unpacked build passed the isolated Edge HTTPS Facebook fixture. It measured a usable open width, then closed an actual completed result and measured `display: none` and zero height. The same fixture checked selected-post switching, source lookup, two English prediction labels, English/Tagalog switching, and a permalink timestamp with no `<time>` element: both the date and relative age appeared. This is a controlled browser fixture, **not** the user's signed-in Facebook session. See [the current browser report](FACEBOOK-MODAL-VERIFICATION.json).

## Source and date checks

A live `POST /analyze` of the complete test claim about the Bureau of Customs destroying P1.4 billion of illicit vape products in 3,174 boxes returned two **readable**, claim-specific supporting articles: [Philstar](https://www.philstar.com/nation/2026/10/02/2560336/boc-destroys-p14-billion-smuggled-vape-products) and [Daily Tribune](https://tribune.net.ph/2026/10/01/boc-destroys-p14-b-smuggled-vape-shipment). Retrieval was `available`; both source cards were marked `supports`. The request took 4.63 seconds in one local run. The original model and final label were both **No Misleading Information Detected**, so evidence did not change the label. The screening decision was saved without storing the submitted text. This demonstrates source recovery for this claim, not every Facebook claim or an accuracy gain.

Post date and “How recent” were visible in the browser fixture from both a real `<time datetime>` and a Facebook-style permalink `aria-label`. If Facebook exposes neither a timestamp nor a readable relative label for a selected post, the UI must still say it cannot determine the date; it must not invent one.

The manual **Find related sources** control is a source-only refresh and preserves the existing decision. A new source card by itself does not retrospectively reclassify that earlier result. A fresh check with source lookup enabled is required for a new evidence-based final decision.
